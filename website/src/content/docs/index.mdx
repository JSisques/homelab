## Estado del proyecto

:::caution[Fase inicial / en construcción]
Este repositorio describe hoy más el diseño *objetivo* del homelab que su estado real en producción. Proxmox, K3s, Argo CD y buena parte del catálogo de `config/services.yaml` se están definiendo aquí primero y desplegando de forma incremental — trata la arquitectura documentada como la dirección, no como una foto de lo que está corriendo en este momento.
:::

Lo que existe hoy en el repositorio:

- Infraestructura declarada con Terraform para Proxmox y configurada con Ansible, servicio a servicio.
- Un catálogo de más de 30 servicios entre monitorización, redes, multimedia, descargas, productividad, automatización, aplicaciones e infraestructura base.
- Un cluster K3s de un solo nodo con Argo CD, listo para Kafka y las aplicaciones de Kubernetes en cuanto haya capacidad de sobra.
- Un flujo GitOps completo: cada push dispara validación en CI, y el despliegue real (`deploy.yaml`) corre en un runner autoalojado contra el Proxmox de verdad.

Nada de esto se ha aplicado todavía contra infraestructura real de producción — trátalo como "listo para desplegar", no como "desplegado". Este sitio y el `README.md` del repositorio se actualizan a medida que cada pieza pasa de "definida en Git" a "corriendo de verdad".

## Diseño

- **Declarativo** — se describe el estado deseado, no una receta de pasos manuales.
- **Reproducible** — el entorno se puede reconstruir por completo desde el repositorio.
- **Versionado** — la infraestructura y la configuración se siguen en Git.
- **Automatizado** — un `git push` debe bastar para disparar el flujo de despliegue necesario.
- **Observable** — todo host y servicio importante expone información útil de salud y rendimiento.
- **Modular** — los servicios son desplegables y configurables de forma independiente.
- **Fuente única de verdad** — los metadatos de cada servicio se definen una vez y se reutilizan para generar la configuración de los distintos sistemas.
